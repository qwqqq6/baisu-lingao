# 状态管理类说明

本文说明 `game/src/engine/state/state-manager.ts` 中的单例状态管理类。它负责维护游戏世界状态，例如“是否接触本地人”“南海农庄进度”“当前劳工政策”“临时戒严还有几天”等。

状态管理类只处理状态定义、状态值、状态变更、条件判断和存档快照，不负责抽卡、UI、人物继任或卡牌结算逻辑。

## 1. 核心职责

`StateManager` 的职责是：

- 注册状态定义。
- 根据定义初始化默认状态。
- 读取和修改运行时状态值。
- 校验状态类型和值是否合法。
- 执行卡牌选项产生的状态变化。
- 判断卡牌出现条件是否满足。
- 推进计时器状态。
- 导出和恢复存档快照。

项目应通过导出的单例使用它：

```ts
import { stateManager } from "../engine/state/state-manager.ts";
```

## 2. 状态定义

状态定义描述一个状态“是什么”。运行时状态值必须符合定义。

```ts
{
  id: "core.farm.nanhai.established",
  name: "南海农庄已建立",
  type: "boolean",
  scope: "global",
  default: false,
  visibility: "hinted",
  mutability: "immutable",
  tags: ["farm", "nanhai"],
  desc: "解锁南海农庄系列卡牌。"
}
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| `id` | 英文命名空间 id，例如 `core.farm.nanhai.established` |
| `name` | 中文名，供编辑器、日志或调试使用 |
| `type` | 状态类型 |
| `scope` | 作用域 |
| `default` | 默认值 |
| `visibility` | 玩家可见性 |
| `mutability` | 可变性规则 |
| `tags` | 分类标签，可选 |
| `desc` | 说明文字，可选 |
| `min` / `max` | 数值状态边界，可选 |
| `values` | `enum` 可选值 |

## 3. 支持类型

| 类型 | 值 | 用途 |
| --- | --- | --- |
| `boolean` | `true` / `false` | 是否发生、是否建立 |
| `counter` | number | 可累计数值，如军事化程度 |
| `level` | number | 等级或阶段，如系列进度 |
| `enum` | string | 当前政策或路线 |
| `timer` | `{ remainingDays }` 或 `null` | 临时状态 |
| `set` | string[] | 已知势力、前任列表等集合 |

数值类型会自动四舍五入，并按 `min` / `max` 裁剪。

## 4. 可变性

`mutability` 控制状态是否允许普通卡牌回滚。

| 值 | 含义 |
| --- | --- |
| `reversible` | 可自由变化，适合政策、等级、临时局势 |
| `immutable` | 历史事实，只能从默认值推进，不能回滚 |
| `terminal` | 终结状态，只能触发一次，通常关闭系列或人物 |

例如“南海农庄已建立”不应改回 `false`。如果农庄后来被毁，应新增 `core.farm.nanhai.destroyed = true`，而不是回滚历史。

## 5. 常用方法

```ts
stateManager.loadDefinitions(definitions);
```

清空旧定义和值，加载一组新定义，并初始化默认值。

```ts
stateManager.define(definition);
```

追加一个状态定义。

```ts
stateManager.get(id);
stateManager.set(id, value);
```

读取或直接设置状态值。`set` 会校验类型、枚举值、数值边界和可变性。

```ts
stateManager.apply(change);
stateManager.applyAll(changes);
```

执行卡牌选项里的状态变化。

```ts
stateManager.matches(condition);
stateManager.matchesAll(conditions);
```

判断单个或多个条件是否满足。

```ts
stateManager.snapshot();
stateManager.restore(snapshot);
stateManager.reset();
```

用于存档、读档和重置。

## 6. 状态变更示例

```ts
stateManager.applyAll([
  {
    id: "core.farm.nanhai.established",
    op: "set",
    value: true,
  },
  {
    id: "core.series.farm.nanhai.progress",
    op: "add",
    value: 1,
  },
  {
    id: "core.known_forces",
    op: "addToSet",
    value: "locals",
  },
]);
```

支持的操作：

| 操作 | 适用类型 |
| --- | --- |
| `set` | 所有类型 |
| `add` / `subtract` | `counter`、`level` |
| `addToSet` / `removeFromSet` | `set` |
| `startTimer` / `clearTimer` | `timer` |

## 7. 条件判断示例

```ts
stateManager.matchesAll([
  {
    state: "core.farm.nanhai.established",
    equals: true,
  },
  {
    state: "core.series.farm.nanhai.progress",
    gte: 2,
  },
]);
```

支持的条件：

- `equals`
- `notEquals`
- `gt` / `gte`
- `lt` / `lte`
- `between`
- `includes`
- `notIncludes`
- `exists`

这些条件会被系列、卡牌和变体复用。

## 8. 计时器

`timer` 状态用于临时效果。

```ts
stateManager.apply({
  id: "core.martial_law.timer",
  op: "startTimer",
  value: 7,
});

stateManager.tickTimers(1);
```

`tickTimers` 会减少剩余天数。倒计时归零后，该状态自动变成 `null`。

## 9. 存档快照

```ts
const snapshot = stateManager.snapshot();
stateManager.restore(snapshot);
```

快照是普通对象，适合写入存档。恢复时会校验状态 id 是否已定义，并补齐快照中缺失的状态默认值。

## 10. 注意事项

- 状态 id 必须使用英文命名空间，例如 `core.labor.policy`。
- 不要用状态管理类保存四柱、隐藏势力或完整卡牌历史；它只管状态库。
- `immutable` 和 `terminal` 状态不要回滚，应用新的后果状态表达变化。
- 引擎、抽卡器和 UI 都应依赖这个类的公开方法，不要直接读写内部 `Map`。
- 后续 Mod 内容也应先注册状态定义，再让卡牌引用状态 id。
